## 1. Обзор предметной области

Модуль предоставляет муниципальным органам управления (Акимат) и администраторам платформы аналитические отчеты по загрузке спортивной инфраструктуры, тепловые карты использования кортов, учет уникальных горожан, мониторинг состояния IoT-шлюзов и интерфейс ручного управления блокировками и апелляциями.

## 3. Функциональные требования (Requirements)

### REQ-ADM-01: Аналитический отчет для Акимата (`GET /analytics/akimat`)
* **Описание**: Агрегация ключевых показателей популяризации спорта в регионе:
  - Общее количество активных граждан, занимающихся спортом.
  - Суммарное количество часов использования площадок за месяц/квартал.
  - Средняя наполняемость кортов в пиковые часы (18:00–22:00).
  - Сравнение показателей по районам и видам спорта.
* **Критерии приемки**:
  - `When`: Поступает запрос на эндпоинт аналитики акимата.
  - `Then`: Возвращается структурированный JSON с разбивкой по городам (Темиртау, Караганда и др.), статистикой загрузки и динамикой прироста пользователей.

### REQ-ADM-02: Почасовая тепловая карта загрузки площадки (Venue Heatmap)
* **Описание**: Сервер рассчитывает матрицу загруженности площадки $7 \times 24$ (дни недели $\times$ часы суток) на основе завершенных броней.
* **Критерии приемки**:
  - `Given`: Запрос `GET /admin/analytics/venues/:venueId/heatmap`.
  - `Then`: Возвращается массив значений от `0.0` (полностью свободно) до `1.0` (100% занято) для каждого часового интервала недели.

### REQ-ADM-03: Мониторинг и ручное управление шлюзами Wi-Fi
* **Описание**: Администратор видит реальный статус каждого шлюза TTLock, время последнего пинга и может принудительно эмулировать офлайн-режим (`POST /admin/gateways/toggle`) для проверки отказоустойчивости.
* **Критерии приемки**:
  - `When`: Администратор нажимает «Переключить статус шлюза».
  - `Then`: Статус шлюза меняется `online` ↔ `offline`, что немедленно тестирует автоматическое переключение на офлайн PIN-коды.

### REQ-ADM-04: Рассмотрение апелляций и снятие банов (Unban Management)
* **Описание**: Администратор может просмотреть реестр заблокированных пользователей (`GET /admin/bans`), ознакомиться с причиной бана и текстом поданного письменного обращения, и досрочно разблокировать пользователя (`POST /admin/users/:userId/unban`).
* **Критерии приемки**:
  - `Given`: Пользователь забанен за задержку на поле.
  - `When`: Администратор нажимает «Разблокировать (Удовлетворить апелляцию)».
  - `Then`: Запись в `User.is_banned` сбрасывается в `false`, `banned_until` обнуляется, статус в `UserBan` отмечается как `is_resolved = true`.

### REQ-ADM-05: Интерактивный веб-дашборд тестирования (`/admin`)
* **Описание**: На роуте `/admin` развернута независимая веб-панель управления и симуляции:
  - Тестирование валидатора ИИН РК.
  - Переключение режимов работы смарт-замка (Mock / Cloud / Gateway).
  - Просмотр логов срабатывания замков в реальном времени.
