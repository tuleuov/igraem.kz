> SDD ref: SPEC-09 | Feature: «Сыграем» — Бизнес-правила

## Создание заявки

**[PLAY-R-01]** Создавать заявки могут только авторизованные пользователи (JWT обязателен).

**[PLAY-R-02]** Забаненный пользователь (`User.is_banned = true` и `banned_until > now()`) не может создавать заявки. Ответ: `403 Forbidden` + `{ code: "USER_BANNED", banned_until: "..." }`.

**[PLAY-R-03]** Обязательные поля формы:
- `sport_type`: `football` | `basketball` | `volleyball`
- `event_date`: строка `YYYY-MM-DD`, не раньше сегодня
- `start_time`: `HH:mm`
- `location_text`: произвольный адрес (min 5, max 200 символов)
- `latitude` + `longitude`: координаты места (геолокация из браузера или ручной выбор на карте при создании)
- `max_participants`: целое число от 2 до 50

**[PLAY-R-04]** Необязательные поля:
- `comment`: свободный текст (max 500 символов)
- `end_time`: `HH:mm` (если не указан — не отображается)

**[PLAY-R-05]** Дата события не может быть в прошлом. Граница: `event_date >= TODAY()` по временной зоне сервера (Asia/Almaty, UTC+5). Ответ на нарушение: `400 Bad Request { code: "DATE_IN_PAST" }`.

**[PLAY-R-06]** `start_time` должно быть >= текущего времени, если `event_date == сегодня`. Ответ: `400 { code: "TIME_IN_PAST" }`.

**[PLAY-R-07]** Один пользователь может иметь не более **5 активных** (статус `open`) заявок одновременно. Ответ: `409 { code: "TOO_MANY_OPEN_PROPOSALS" }`.

**[PLAY-R-08]** Место (`location_text` + координаты) — свободное поле. Оно **не обязано** совпадать с площадками из таблицы `grounds`. Пользователь может указать любое место.

## Участие в заявке

**[PLAY-R-09]** Организатор не может подавать заявку на участие в своей же игре.

**[PLAY-R-10]** Пользователь может подать заявку на участие только если статус предложения = `open`.

**[PLAY-R-11]** Нельзя подать повторную заявку, если предыдущая в статусе `PENDING` или `APPROVED`. Ответ: `409 { code: "ALREADY_REQUESTED" }`.

**[PLAY-R-12]** Забаненный пользователь не может подавать заявки на участие. Ответ: `403 { code: "USER_BANNED" }`.

**[PLAY-R-13]** Если количество `APPROVED` участников достигает `max_participants - 1` (включая организатора), заявки на участие больше не принимаются (статус не меняется, но новые `ProposalParticipant` не создаются). Ответ: `409 { code: "PROPOSAL_FULL" }`.

**[PLAY-R-14]** Организатор одобряет (`APPROVED`) или отклоняет (`REJECTED`) каждого участника вручную. Автоодобрения нет (в отличие от matchmaking booking с `auto_approve_players`).

**[PLAY-R-15]** Одобренный (`APPROVED`) участник может сам отказаться от участия (`WITHDRAWN`). При этом освобождается место.

**[PLAY-R-16]** Организатор может удалить одобренного участника (kick). Статус переходит в `REMOVED`.

## Чат внутри заявки

**[PLAY-R-17]** Писать в чат может: организатор + любой пользователь, чья заявка на участие в статусе `PENDING`, `APPROVED` (т.е. любой заинтересованный, не только одобренные). Это позволяет участникам задавать вопросы до одобрения.

**[PLAY-R-18]** Забаненный пользователь не может писать в чат. Ответ: `403 { code: "USER_BANNED" }`.

**[PLAY-R-19]** Максимальная длина сообщения: 1000 символов.

**[PLAY-R-20]** Сообщения хранятся и не удаляются (кроме удаления администратором). Редактирование сообщений не предусмотрено в MVP.

**[PLAY-R-21]** Сообщения доставляются в режиме реального времени через WebSocket (или polling каждые 5 сек в MVP, если WS не подключён). Endpoint получения истории чата — REST.

**[PLAY-R-22]** Пользователи, чья заявка `REJECTED` или `REMOVED`, теряют доступ к чату (не могут писать новые сообщения; уже написанные видны).

## Статус заявки и переходы

**[PLAY-R-23]** Переходы статусов:

| Текущий | Событие | Новый |
|---|---|---|
| `open` | Организатор отменяет | `cancelled` |
| `open` | Наступило `event_date + start_time` | `in_progress` (авто) |
| `in_progress` | Организатор завершает вручную | `completed` |
| `in_progress` | Прошло `end_time` + 2 часа (или +4ч если end_time не задан) | `completed` (авто cron) |
| `open` / `in_progress` | Нет ни одного участника через 1ч после `start_time` | `completed` (авто) |

**[PLAY-R-24]** Заявки в статусе `cancelled` и `completed` скрываются из публичного списка и карты. Остаются доступны по прямой ссылке для участников.

**[PLAY-R-25]** Редактировать заявку (`location_text`, `comment`, `max_participants`, `end_time`) можно только пока статус = `open`. Нельзя менять `sport_type`, `event_date`, `start_time` после создания.

## Фильтрация и карта

**[PLAY-R-26]** Публичный список и карта показывают только заявки со статусом `open` или `in_progress`.

**[PLAY-R-27]** Карта по умолчанию фильтрует на `event_date = сегодня`. При смене фильтра дата меняется.

**[PLAY-R-28]** Доступные фильтры: `sport_type` (мультивыбор), `event_date` (конкретная дата), `start_time_from` / `start_time_to` (временной диапазон).

**[PLAY-R-29]** Фильтры применяются одинаково и к списку, и к карте (единый query string).

**[PLAY-R-30]** Маркеры на карте кластеризуются при удалении (zoom ≤ 12). Тап на кластер — zoom in. Тап на одиночный маркер — всплывающая мини-карточка с кнопкой «Открыть».

## Уведомления (push / in-app)

**[PLAY-R-31]** Организатор получает уведомление когда:
- Кто-то подал заявку на участие (`PENDING`).
- Участник самостоятельно отказался (`WITHDRAWN`).

**[PLAY-R-32]** Участник получает уведомление когда:
- Его заявка одобрена (`APPROVED`).
- Его заявка отклонена (`REJECTED`).
- Его кикнули (`REMOVED`).
- Организатор написал в чат (если участник `APPROVED`).
- Заявка отменена (`cancelled`).

**[PLAY-R-33]** В MVP уведомления реализуются как in-app (бейдж на иконке раздела + список уведомлений). Push-уведомления — следующая итерация.

## Модерация / Admin

**[PLAY-R-34]** Администратор может удалить любую заявку (`DELETE /api/v1/admin/play-proposals/:id`) без объяснений.

**[PLAY-R-35]** При бане пользователя (`UserBan`) все его `open` заявки автоматически переходят в `cancelled`.
