# 🔒 Бизнес-сценарий: Открытие смарт-замка TTLock

> **Модуль**: `features/booking` (`UnlockLoadingScreen.tsx`)  
> **Цель**: Бесконтактный доступ на площадку через интерактивную анимацию отпирания электронного замка TTLock.

---

## 1. Описание сценария

При наступлении забронированного времени у пользователя (Организатора или Присоединившегося участника) активируется возможность открыть дверь площадки через карточку бронирования.

---

## 2. Этапы выполнения (Stages)

1. **Stage 1: Инициализация и Проверка прав**
   * Вызов экрана `UnlockLoadingScreen.tsx`.
   * Анимация пульсирующих зелёных колец вокруг центральной иконки замка.
   * Текст: *«Проверка прав доступа и геопозиции...»*.

2. **Stage 2: Подключение к замку TTLock**
   * Вызов бэкенд API `POST /api/v1/bookings/:id/unlock`.
   * Бэкенд связывается с TTLock Cloud API с использованием вендорских токенов.
   * Текст: *«Отправка цифрового ключа на смарт-замок...»*.

3. **Stage 3: Успешное отпирание**
   * Замок физически издает сигнал и открывается.
   * Зелёный индикатор выполнения заполняется до 100%.
   * Текст: *«Дверь разблокирована! Проходите на площадку»*.
   * Для участника статус в списке игроков меняется на **«Вошёл»** (`entered`).
   * Состояние брони переводится в `isOpened = true`, и открывается экран активной сессии `VenueOpenedScreen`.

---

## 3. Автоматическое тестовое покрытие (Automated Unit Tests)
* **Файл тестов**: `src/services/ttlockService.test.ts`
* **Проверяемые сценарии**:
  * Отпирание замка в режиме `online_cloud` при активном сетевом шлюзе.
  * Автоматическое переключение в резервный автономный режим `offline_passcode` при сбое соединения со шлюзом.
  * Мониторинг статуса шлюза TTLock Cloud.
